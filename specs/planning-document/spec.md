# Plan document contract

| Field   | Value                                                                                                                 |
| ------- | --------------------------------------------------------------------------------------------------------------------- |
| Status  | Shipped                                                                                                               |
| Package | `@re-cinq/planning-document`                                                                                          |
| ADRs    | [ADR-001](../../adrs/ADR-001-packages-and-ports.md), [ADR-002](../../adrs/ADR-002-yjs-is-truth-json-is-projection.md) |

The plan document is the JSON every consumer of a plan reads: the host application and the planning agent. A plan ends at approval; whatever is built from it afterwards, tickets included, lives outside the plan. This spec states what the contract guarantees, and each statement links the tests that prove it.

## Blocks

- A plan block accepts only the props its config declares, fills a missing prop with its configured default, and rejects an enum value outside its list ([validated by](../../packages/planning-document/src/blocks/plan-blocks.test.ts#L6), [validated by](../../packages/planning-document/src/blocks/plan-blocks.test.ts#L28), [validated by](../../packages/planning-document/src/blocks/plan-blocks.test.ts#L38), [validated by](../../packages/planning-document/src/blocks/plan-blocks.test.ts#L59), [validated by](../../packages/planning-document/src/blocks/plan-blocks.test.ts#L74), [validated by](../../packages/planning-document/src/blocks/plan-blocks.test.ts#L78), [validated by](../../packages/planning-document/src/blocks/plan-blocks.test.ts#L82), [validated by](../../packages/planning-document/src/blocks/plan-blocks.test.ts#L88)).
- A section heading carries no inline content ([validated by](../../packages/planning-document/src/blocks/plan-blocks.test.ts#L49)).
- Custom plan blocks and prose blocks are told apart by their type ([validated by](../../packages/planning-document/src/blocks/plan-blocks.test.ts#L94), [validated by](../../packages/planning-document/src/blocks/plan-blocks.test.ts#L98), [validated by](../../packages/planning-document/src/blocks/prose-blocks.test.ts#L86), [validated by](../../packages/planning-document/src/blocks/prose-blocks.test.ts#L90), [validated by](../../packages/planning-document/src/blocks/block-json.test.ts#L73)).
- Prose is limited to paragraphs, level 2 and 3 headings, nestable lists, quotes, code and tables; images, video and any other heading level are refused ([validated by](../../packages/planning-document/src/blocks/prose-blocks.test.ts#L6), [validated by](../../packages/planning-document/src/blocks/prose-blocks.test.ts#L26), [validated by](../../packages/planning-document/src/blocks/prose-blocks.test.ts#L38), [validated by](../../packages/planning-document/src/blocks/prose-blocks.test.ts#L48), [validated by](../../packages/planning-document/src/blocks/prose-blocks.test.ts#L58), [validated by](../../packages/planning-document/src/blocks/prose-blocks.test.ts#L68), [validated by](../../packages/planning-document/src/blocks/prose-blocks.test.ts#L74), [validated by](../../packages/planning-document/src/blocks/block-json.test.ts#L42), [validated by](../../packages/planning-document/src/blocks/block-json.test.ts#L49)).
- Any block parses through one entry point that picks the plan or prose schema, and filtering blocks by type keeps document order ([validated by](../../packages/planning-document/src/blocks/block-json.test.ts#L11), [validated by](../../packages/planning-document/src/blocks/block-json.test.ts#L25), [validated by](../../packages/planning-document/src/blocks/block-json.test.ts#L55), [validated by](../../packages/planning-document/src/blocks/block-json.test.ts#L67)).
- Inline content is text nodes and links whose plain text joins in order, with styles defaulting to none ([validated by](../../packages/planning-document/src/blocks/inline-text.test.ts#L10), [validated by](../../packages/planning-document/src/blocks/inline-text.test.ts#L16), [validated by](../../packages/planning-document/src/blocks/inline-text.test.ts#L29), [validated by](../../packages/planning-document/src/blocks/inline-text.test.ts#L35), [validated by](../../packages/planning-document/src/blocks/inline-text.test.ts#L41), [validated by](../../packages/planning-document/src/blocks/inline-text.test.ts#L45), [validated by](../../packages/planning-document/src/blocks/inline-text.test.ts#L53), [validated by](../../packages/planning-document/src/blocks/inline-text.test.ts#L59)).

## Metadata and entities

- Plan metadata names an owner/repo, one of five plan kinds, schema version 1, and an optional approval that points at the version it approved ([validated by](../../packages/planning-document/src/plan/plan-meta.test.ts#L20), [validated by](../../packages/planning-document/src/plan/plan-meta.test.ts#L24), [validated by](../../packages/planning-document/src/plan/plan-meta.test.ts#L41), [validated by](../../packages/planning-document/src/plan/plan-meta.test.ts#L47), [validated by](../../packages/planning-document/src/plan/plan-meta.test.ts#L53)).
- A KPI states its metric, baseline, target, a direction of up, down or hold, its deadline and its rationale ([validated by](../../packages/planning-document/src/plan/entities.test.ts#L6), [validated by](../../packages/planning-document/src/plan/entities.test.ts#L19)).

## Templates

- Each plan kind has an ordered template: a feature runs from intent to open questions, and an incident response starts with what happened ([validated by](../../packages/planning-document/src/template/templates.test.ts#L14), [validated by](../../packages/planning-document/src/template/templates.test.ts#L27)).
- A refactor plan adds a risk section ([validated by](../../packages/planning-document/src/template/templates.test.ts#L31)).
- A UI change always needs a prototype of at least click-dummy maturity ([validated by](../../packages/planning-document/src/template/templates.test.ts#L35)).
- Every template asks for at least one KPI, and no template repeats a section ([validated by](../../packages/planning-document/src/template/templates.test.ts#L42), [validated by](../../packages/planning-document/src/template/templates.test.ts#L51)).
- Looking up a section a template does not have throws UnknownSlotError ([validated by](../../packages/planning-document/src/template/templates.test.ts#L61), [validated by](../../packages/planning-document/src/template/templates.test.ts#L68)).

## Projection

- A section heading opens a section and every block up to the next heading belongs to it; a block before the first heading is an error ([validated by](../../packages/planning-document/src/projection/partition.test.ts#L43), [validated by](../../packages/planning-document/src/projection/partition.test.ts#L59), [validated by](../../packages/planning-document/src/projection/partition.test.ts#L72), [validated by](../../packages/planning-document/src/projection/partition.test.ts#L76)).
- A section's comments and then its panel lead the section, ahead of what people write, so an editor can set them in the margin beside it; its actions close it ([validated by](../../packages/planning-document/src/projection/partition.test.ts#L89)).
- The feature's name is the plan's title, written above the first section and belonging to no section ([validated by](../../packages/planning-document/src/projection/partition.test.ts#L20), [validated by](../../packages/planning-document/src/projection/partition.test.ts#L28), [validated by](../../packages/planning-document/src/projection/partition.test.ts#L32)).
- The KPIs and the first prototype declaration are read out of the blocks wherever they sit ([validated by](../../packages/planning-document/src/projection/derive-views.test.ts#L7), [validated by](../../packages/planning-document/src/projection/derive-views.test.ts#L48), [validated by](../../packages/planning-document/src/projection/derive-views.test.ts#L66)).
- Projecting the blocks gives a plan document the schema accepts, with its sections and derived views ([validated by](../../packages/planning-document/src/projection/round-trip.test.ts#L40), [validated by](../../packages/planning-document/src/projection/round-trip.test.ts#L49)).
- The round trip holds both ways: blocks to plan to blocks, and plan to blocks to plan ([validated by](../../packages/planning-document/src/projection/round-trip.test.ts#L58), [validated by](../../packages/planning-document/src/projection/round-trip.test.ts#L64)).
- A new plan is seeded with its title, then one heading, one panel and one actions block per template section, in template order, with generated ids ([validated by](../../packages/planning-document/src/projection/round-trip.test.ts#L71), [validated by](../../packages/planning-document/src/projection/round-trip.test.ts#L87), [validated by](../../packages/planning-document/src/projection/round-trip.test.ts#L94)).

## Agent edits

- The agent writes a section's prose without touching the plan blocks that live in it, and can append to what is already there ([validated by](../../packages/planning-document/src/ops/apply-ops.test.ts#L40), [validated by](../../packages/planning-document/src/ops/apply-ops.test.ts#L54), [validated by](../../packages/planning-document/src/ops/apply-ops.test.ts#L67)).
- A KPI and a prototype declaration are written by id, so sending one twice updates it instead of adding a second ([validated by](../../packages/planning-document/src/ops/apply-ops.test.ts#L77), [validated by](../../packages/planning-document/src/ops/apply-ops.test.ts#L97), [validated by](../../packages/planning-document/src/ops/apply-ops.test.ts#L114)).
- A rewritten KPI keeps its block id, so a person working in it keeps their cursor ([validated by](../../packages/planning-document/src/ops/apply-ops.test.ts#L138)).

## Refining a section

- A refine works from settled inputs only: answered questions and resolved comment threads, replies included. Unanswered questions and open threads are handed over as talk to leave alone ([validated by](../../packages/planning-document/src/refine/refine-inputs.test.ts#L43), [validated by](../../packages/planning-document/src/refine/refine-inputs.test.ts#L64)).
- The inputs name the questions and threads a proposal uses, and once they are marked used, the next refine does not write them in again ([validated by](../../packages/planning-document/src/refine/refine-inputs.test.ts#L73), [validated by](../../packages/planning-document/src/refine/refine-inputs.test.ts#L81), [validated by](../../packages/planning-document/src/refine/refine-inputs.test.ts#L88)).
- A section's hash covers what a refine would rewrite, so a new comment or answer leaves it alone and a rewritten paragraph changes it ([validated by](../../packages/planning-document/src/refine/section-hash.test.ts#L12), [validated by](../../packages/planning-document/src/refine/section-hash.test.ts#L21), [validated by](../../packages/planning-document/src/refine/section-hash.test.ts#L27), [validated by](../../packages/planning-document/src/refine/section-hash.test.ts#L32)).
- A proposal is asked for against a section hash and carries the agent's ops and the inputs they use ([validated by](../../packages/planning-document/src/refine/refine-proposal.test.ts#L24), [validated by](../../packages/planning-document/src/refine/refine-proposal.test.ts#L38)).
- A proposal's ops stay inside its own section; one that reaches another section is refused with ProposalScopeError ([validated by](../../packages/planning-document/src/refine/refine-proposal.test.ts#L46), [validated by](../../packages/planning-document/src/refine/refine-proposal.test.ts#L50)).
- A preview shows what accepting would change, line by line, and says when the section changed after the refine was asked for ([validated by](../../packages/planning-document/src/refine/proposal-preview.test.ts#L43), [validated by](../../packages/planning-document/src/refine/proposal-preview.test.ts#L53), [validated by](../../packages/planning-document/src/refine/proposal-preview.test.ts#L60)).

## Versions

- Two versions differ by the lines people wrote: shared lines are kept, and the longest common run survives a change in the middle ([validated by](../../packages/planning-document/src/versions/diff-plans.test.ts#L30), [validated by](../../packages/planning-document/src/versions/diff-plans.test.ts#L37), [validated by](../../packages/planning-document/src/versions/diff-plans.test.ts#L44)).
- A plan diff shows the sections that changed and leaves out the ones nobody touched ([validated by](../../packages/planning-document/src/versions/diff-plans.test.ts#L55), [validated by](../../packages/planning-document/src/versions/diff-plans.test.ts#L69)).
- KPIs are compared by their id, as added, changed or removed ([validated by](../../packages/planning-document/src/versions/diff-plans.test.ts#L80), [validated by](../../packages/planning-document/src/versions/diff-plans.test.ts#L86), [validated by](../../packages/planning-document/src/versions/diff-plans.test.ts#L93)).
- A plan's move from draft to approved is part of the diff ([validated by](../../packages/planning-document/src/versions/diff-plans.test.ts#L100)).

## Validation

- A draft needs only its always-required sections, approval adds the for-approval ones, and an optional section is never required ([validated by](../../packages/planning-document/src/validation/problems.test.ts#L6), [validated by](../../packages/planning-document/src/validation/problems.test.ts#L10), [validated by](../../packages/planning-document/src/validation/problems.test.ts#L14), [validated by](../../packages/planning-document/src/validation/problems.test.ts#L18), [validated by](../../packages/planning-document/src/validation/problems.test.ts#L24), [validated by](../../packages/planning-document/src/validation/problems.test.ts#L28)).
- A freshly seeded plan passes at draft and a complete one passes at approval ([validated by](../../packages/planning-document/src/validation/validate-plan.test.ts#L55), [validated by](../../packages/planning-document/src/validation/validate-plan.test.ts#L63)).
- At approval every required section needs real content, a whitespace-only paragraph does not count, and the KPI and prototype counts must be met ([validated by](../../packages/planning-document/src/validation/validate-plan.test.ts#L69), [validated by](../../packages/planning-document/src/validation/validate-plan.test.ts#L125), [validated by](../../packages/planning-document/src/validation/validate-plan.test.ts#L134)).
- At any phase a missing, unknown or out-of-order section is reported, and so is a block outside its section's allowed kinds ([validated by](../../packages/planning-document/src/validation/validate-plan.test.ts#L91), [validated by](../../packages/planning-document/src/validation/validate-plan.test.ts#L97), [validated by](../../packages/planning-document/src/validation/validate-plan.test.ts#L103), [validated by](../../packages/planning-document/src/validation/validate-plan.test.ts#L116)).
- A section's own tools and the comments under it are allowed wherever they appear, and a section holding only those is still empty ([validated by](../../packages/planning-document/src/validation/validate-plan.test.ts#L81), [validated by](../../packages/planning-document/src/validation/validate-plan.test.ts#L69)).
- A plan whose template sets a prototype minimum is refused at approval when its declared maturity is below it ([validated by](../../packages/planning-document/src/validation/validate-plan.test.ts#L147)).

## Document naming

- A plan document is named plan:owner/repo:uuid, and any other name or malformed part is refused with DocNameError ([validated by](../../packages/planning-document/src/naming/doc-name.test.ts#L8), [validated by](../../packages/planning-document/src/naming/doc-name.test.ts#L14), [validated by](../../packages/planning-document/src/naming/doc-name.test.ts#L20), [validated by](../../packages/planning-document/src/naming/doc-name.test.ts#L28), [validated by](../../packages/planning-document/src/naming/doc-name.test.ts#L35), [validated by](../../packages/planning-document/src/naming/doc-name.test.ts#L40), [validated by](../../packages/planning-document/src/naming/doc-name.test.ts#L46)).
